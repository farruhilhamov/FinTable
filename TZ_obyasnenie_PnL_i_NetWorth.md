# ТЗ: Объяснение P&L, разбивка Net Worth и Pie-диаграмма структуры капитала

Дополнение к основному ТЗ "Учёт финансовых средств" (модуль `analytics`). Описывает функцию автоматического объяснения причин изменения P&L, детализацию состава Net Worth и визуализацию структуры капитала.

## 1. Назначение

Пользователю недостаточно видеть цифру "P&L за месяц: −450 000 UZS" — нужно понимать **за счёт чего** так получилось и **что именно** входит в Net Worth. Модуль добавляет человекочитаемую сводку-объяснение с двумя уровнями глубины (простой и расширенный) и наглядную визуализацию состава капитала.

## 2. Объяснение P&L — автоматическая сводка

### 2.1 Уровень 1 — простая сводка (показывается всегда, по умолчанию)

Короткий текстовый блок (2–4 предложения) над графиком P&L на Dashboard/Статистике, генерируемый по шаблону на основе реальных цифр периода:

> "Ваш P&L за август 2026 составил −450 000 UZS (в июле было +200 000 UZS). Основная причина падения — рост расходов на категорию 'Кафе и рестораны' (+320 000 UZS по сравнению с прошлым месяцем). Доход от вклада 'Депозит в Kapitalbank' продолжает расти стабильно (+45 000 UZS)."

**Логика формирования (шаблонная, без ML):**
1. Взять P&L текущего периода и P&L предыдущего периода той же длины (сравнение "период к период", period-over-period).
2. Посчитать разницу (`delta = pnl_current - pnl_previous`) и определить направление (рост/падение).
3. Для каждой категории расходов и доходов посчитать вклад в изменение: `category_delta = sum(category, current_period) - sum(category, previous_period)`.
4. Отсортировать категории по модулю `category_delta` по убыванию, взять топ-1 или топ-2 категории с наибольшим вкладом в изменение — это и есть "основная причина".
5. Отдельно упомянуть вклад от вкладов (изменение накопленного дохода) и от переоценки долей/ценных бумаг, если их вклад в `delta` превышает заданный порог (например, >10% от общей величины изменения).
6. Собрать текст по шаблону: `"Ваш P&L за {период} составил {pnl_current} (в {предыдущий период} было {pnl_previous}). Основная причина {роста/падения} — {направление} категории '{топ-категория}' ({знак}{сумма} по сравнению с {предыдущий период})."` + опционально второе предложение про вклад/долю, если релевантно.

### 2.2 Уровень 2 — расширенный анализ (по запросу, кнопка "Показать подробнее")

При клике разворачивается детализированная секция:

- **Таблица вклада категорий в изменение P&L**: категория, сумма текущий период, сумма предыдущий период, разница, % от общего изменения — отсортировано по убыванию влияния.
- **Обнаружение аномальных транзакций**: транзакции текущего периода, сумма которых превышает среднюю сумму по этой категории за последние N периодов (например, 6 месяцев) более чем в 2 раза (простое статистическое правило, `amount > mean + 2*stddev` или `amount > 2 * avg_historical`). Выводятся как список: "Обнаружена нетипичная операция: 'Кафе и рестораны', 850 000 UZS, 15.08.2026 — это в 3.2 раза больше средней транзакции по этой категории."
- **Разбивка по трём компонентам P&L** (см. предыдущее ТЗ): операционный P&L (доходы−расходы), доход от вкладов, изменение стоимости долей — отдельными числами с указанием динамики каждого компонента относительно предыдущего периода.
- **Мини-график** "P&L по компонентам" (stacked bar по трём составляющим за последние 6 периодов).

### 2.3 Техническая реализация

- Сервис-функция `explain_pnl_change(user, date_from, date_to)` в `analytics/services.py`, возвращающая структурированный dict: `{summary_text, top_factors: [...], anomalies: [...], components: {...}}`.
- Frontend рендерит `summary_text` как есть (сгенерирован на backend), расширенный блок — через сворачиваемый `<details>`/Alpine.js toggle, подгружающий `top_factors`, `anomalies`, `components` без дополнительного запроса (данные приходят в одном ответе).
- Функция должна работать на агрегирующих ORM-запросах (`annotate`, `Sum`, оконные функции для сравнения периодов), не на построчных Python-циклах.

## 3. Net Worth — детализация состава

### 3.1 Что входит в Net Worth (напоминание из основного ТЗ)

Net Worth = сумма остатков по всем Account (карты/наличные) + сумма текущих балансов активных Deposit (принципал + накопленный доход) + сумма текущих оценок Security (доли/ценные бумаги).

### 3.2 Разбивка на dashboard

Рядом с общей цифрой Net Worth отображается блок разбивки по трём укрупнённым категориям с суммой и процентом от общего:

| Компонент | Сумма (UZS) | % от Net Worth |
|---|---|---|
| Деньги на картах/наличные | сумма всех Account.balance | % |
| Вклады (принципал + накопленный доход) | сумма всех активных Deposit.current_balance | % |
| Доля в компании / ценные бумаги | сумма текущих оценок Security | % |

При клике на строку — переход к детальному списку (например, клик на "Вклады" открывает список всех вкладов с их индивидуальными суммами).

### 3.3 Pie-диаграмма структуры капитала

- Отдельная pie-диаграмма (Chart.js) на Dashboard рядом с цифрой Net Worth, показывающая именно три укрупнённых сегмента: **Карты/наличные**, **Вклады**, **Доля/ценные бумаги** — с процентом и суммой в подсказке (tooltip) при наведении.
- Каждый сегмент кликабелен и ведёт на соответствующий раздел (Счета/Вклады/Ценные бумаги).
- Если у пользователя один из компонентов равен нулю (например, нет доли) — сегмент не отображается в диаграмме (не рисуется "пустой" ноль), легенда показывает только непустые категории.
- Диаграмма пересчитывается на текущую дату при каждой загрузке страницы (Net Worth и накопленный доход по вкладам — динамические величины).

*Примечание: pie-диаграмма расходов по категориям за период, заложенная в основном ТЗ (раздел "Статистика"), остаётся отдельной, самостоятельной диаграммой — не путать с этой pie-диаграммой структуры Net Worth.*

## 4. Период по умолчанию — "текущий месяц"

- Во всех разделах, где применим фильтр периода (Dashboard, Статистика, Транзакции, объяснение P&L), значение по умолчанию при первой загрузке страницы — **с 1 числа текущего месяца по сегодняшнюю дату** (month-to-date). Например, при открытии 22.08.2026 диапазон по умолчанию — 01.08.2026–22.08.2026.
- Пользователь может изменить диапазон через date-picker; выбранный диапазон сохраняется в query-параметрах URL (`?date_from=2026-08-01&date_to=2026-08-22`), чтобы страницу можно было обновить/поделиться ссылкой без потери фильтра.
- Для объяснения P&L "предыдущий период" при таком дефолте — это **эквивалентная часть предыдущего месяца** (01.07.2026–22.07.2026), чтобы сравнение было корректным по количеству дней, а не искажённым сравнением полного месяца с неполным.

## 5. Модель данных (дополнение)

Не требует новых таблиц — модуль целиком строится на существующих моделях (Transaction, Category, Deposit, Security, SecurityValuation, Account) через сервис-слой аналитики. Опционально можно кэшировать результат `explain_pnl_change` на уровне запроса (не в БД), так как он пересчитывается каждый раз при открытии страницы за динамический период.

## 6. Критерии готовности

- При открытии Dashboard/Статистики без указания периода отображаются данные с 1 числа текущего месяца по сегодня.
- Текстовая сводка P&L корректно называет категорию с наибольшим вкладом в изменение и совпадает с ручным расчётом на тестовых данных.
- Расширенный блок анализа корректно находит как минимум одну аномальную транзакцию на тестовом наборе данных с искусственно завышенной суммой.
- Pie-диаграмма Net Worth показывает три сегмента (или меньше, если какой-то компонент пуст), сумма процентов равна 100%, суммы совпадают с данными на странице Счета/Вклады/Ценные бумаги.
- Сравнение периодов для объяснения P&L использует эквивалентные по длине периоды (день-к-дню), а не календарный месяц целиком, если текущий период неполный.
