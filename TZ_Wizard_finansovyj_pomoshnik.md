# ТЗ: Wizard — помощник первичного заполнения финансового профиля

Дополнение к основному ТЗ "Учёт финансовых средств". Описывает отдельный модуль `onboarding` (или `wizard`), который проводит пользователя через пошаговый ввод стартовых данных.

## 1. Назначение

Wizard решает проблему "пустого экрана" после регистрации: вместо того чтобы пользователь сам разбирался, куда заходить и что заполнять первым (Счета? Вклады? Категории?), сервис сразу проводит его по 5 коротким шагам и на выходе создаёт полностью рабочий финансовый профиль — счета с текущими остатками, вклады, доля в компании и шаблон зарплаты.

## 2. Момент запуска

- Wizard запускается **автоматически один раз** сразу после успешной регистрации (первый вход в систему).
- На первом экране Wizard пользователю показывается предупреждение перед стартом:

  > "Этот мастер поможет быстро внести ваши текущие финансы. Он займёт 3–5 минут и покрывает только основные функции — счета, вклады, доля и зарплата. Более детальную настройку (категории, регулярные расходы, редактирование) вы всегда сможете сделать позже в настройках."

- Пользователь может нажать **"Отменить"** на любом шаге — тогда:
  - Все уже введённые в рамках этой сессии Wizard данные **сохраняются** (см. раздел 5 про транзакционность) — они не откатываются автоматически, пользователь просто выходит из мастера, в дальнейшем сможет донастроить данные в обычных разделах.
  - Альтернатива — явная кнопка **"Начать заново / отменить всё"**, которая полностью откатывает все изменения, сделанные в текущей сессии Wizard (реализуется через DB-транзакцию, см. п.5). Обе опции должны быть доступны: "Отменить и сохранить, что уже ввёл" и "Отменить и удалить всё, что ввёл".
- После однократного прохождения (или отмены) флаг `user.profile.onboarding_completed = True` не выставляется автоматически при отмене — только при полном завершении всех 5 шагов, либо при явном "пропустить мастер" (см. п.6).

## 3. Повторный запуск Wizard

- Wizard остаётся доступен пользователю в любой момент — реализуется как пункт меню **"Настройки" → "Быстрая настройка профиля" (запустить мастер снова)**.
- При повторном запуске Wizard предупреждает: "Повторное прохождение мастера позволит добавить новые счета/вклады/доли. Существующие данные не будут изменены — мастер только добавляет новые записи." (то есть Wizard всегда работает в режиме **добавления**, не редактирования — редактирование существующих сущностей остаётся на обычных страницах Счета/Вклады/Ценные бумаги).
- Кнопка запуска мастера дублируется на Dashboard небольшим виджетом-подсказкой, если `onboarding_completed = False` ("Вы не завершили настройку профиля — продолжить?").

## 4. Шаги Wizard (multi-step, с прогресс-баром)

Прогресс-бар из 5 шагов, отображается заголовок "Шаг X из 5". Каждый шаг — отдельный экран/URL (`/wizard/step/1/`, `/wizard/step/2/` и т.д.), данные сохраняются по завершении каждого шага (см. п.5).

**Шаг 1 — Приветствие и предупреждение.**
Текст из п.2. Кнопки: "Начать" / "Пропустить мастер" (см. п.6).

**Шаг 2 — Счета (текущие остатки).**
Динамическая форма (formset), позволяющая добавить несколько счетов сразу: название, тип (карта/наличные/другое), текущий остаток (UZS). Кнопка "+ Добавить ещё счёт". Минимум 0 записей (можно пропустить шаг, если денег на картах нет).

**Шаг 3 — Вклады.**
Formset: название вклада, банк/сумма принципала, годовая ставка (%), дата открытия, тип капитализации (простая/сложная). Система сразу показывает предпросмотр расчёта: "Накопленный доход на сегодня: X UZS" — до сохранения, чтобы пользователь мог проверить корректность введённых данных. Можно добавить 0 или несколько вкладов.

**Шаг 4 — Доля в компании / ценные бумаги.**
Formset: название, стоимость приобретения, текущая оценка (создаёт первую запись SecurityValuation с датой = сегодня). Можно добавить 0 или несколько записей.

**Шаг 5 — Доход (зарплата).**
Форма: сумма зарплаты (UZS), день месяца получения, "создавать эту операцию автоматически каждый месяц?" (чекбокс, по умолчанию включён). Если включено — создаётся `RecurringTemplate` с категорией "Зарплата" и указанным `day_of_month`. Если выключено — просто справочная информация, ничего не создаётся (пользователь позже вносит доходы вручную).

**Финальный экран — Итог.**
Сводка того, что создано ("Добавлено: 2 счёта, 1 вклад, 1 доля, шаблон зарплаты"), кнопка "Перейти в Dashboard". Здесь выставляется `onboarding_completed = True`.

## 5. Техническая реализация (Django-специфика)

**Хранение промежуточного состояния:**
- Используется `django-formtools` (`SessionWizardView` или `NamedUrlSessionWizardView`) — стандартный подход Django для multi-step форм с сохранением состояния между шагами в сессии пользователя, без записи в основную БД до финального шага.
- Пока пользователь не дошёл до последнего шага (или не нажал "Сохранить и продолжить позже"), все введённые данные хранятся **только в сессии** (`request.session`), а не в таблицах Account/Deposit/Security — это даёт "бесплатную" отмену: если пользователь просто закрывает вкладку или жмёт "Отменить и удалить всё", достаточно очистить сессию, реальные данные в БД не создаются вообще.

**Точка фактической записи в БД:**
- Данные реально пишутся в БД (Account, Deposit, Security, SecurityValuation, RecurringTemplate) только на **финальном шаге**, внутри единой атомарной транзакции:
  ```python
  from django.db import transaction

  with transaction.atomic():
      # создание Account, Deposit, Security, RecurringTemplate из данных сессии
      ...
      user.profile.onboarding_completed = True
      user.profile.save()
  ```
- Если на финальном шаге происходит ошибка валидации (например, отрицательная сумма) — транзакция откатывается целиком, пользователь возвращается на проблемный шаг с указанием ошибки, данные в БД не создаются частично.

**Опция "Сохранить и продолжить позже" (для случая отмены с сохранением):**
- Если пользователь явно жмёт "Отменить и сохранить, что уже ввёл" на промежуточном шаге (не финальном), система выполняет **частичную запись** — по уже пройденным шагам создаются реальные записи в БД (тем же атомарным блоком, но только для заполненных шагов), `onboarding_completed` остаётся `False`, и на Dashboard показывается подсказка "продолжить настройку" (см. п.3).
- Если пользователь жмёт "Отменить и удалить всё" — сессия Wizard просто очищается (`storage.reset()` в django-formtools), в БД ничего не создавалось, значит и откатывать нечего.

**Идемпотентность при повторном запуске:**
- Так как повторный Wizard всегда работает в режиме добавления (не трогает существующие записи), повторные прохождения безопасны — не возникает конфликтов с уже созданными Account/Deposit/Security.

## 6. Кнопка "Пропустить мастер"

- На Шаге 1 доступна кнопка "Пропустить мастер" — сразу переводит на Dashboard, `onboarding_completed` выставляется в `True` (считается, что пользователь осознанно отказался), но виджет-подсказка на Dashboard остаётся видимым ещё некоторое время (или до первого добавления вручную хотя бы одного счёта) с текстом "Хотите заполнить профиль быстрее? Запустить мастер".

## 7. Модель данных (дополнение)

Добавляется поле в существующую модель профиля пользователя (или создаётся `UserProfile`, если её ещё нет):

- `onboarding_completed` (bool, default=False)
- `onboarding_skipped` (bool, default=False) — чтобы отличить "прошёл" от "пропустил" в аналитике использования.

## 8. Критерии готовности

- Новый пользователь после регистрации автоматически видит Шаг 1 Wizard с предупреждением о его коротком/базовом характере.
- Прохождение всех 5 шагов создаёт корректные записи Account/Deposit/Security/RecurringTemplate, видимые сразу на Dashboard.
- Отмена на любом промежуточном шаге предлагает выбор "сохранить введённое" или "удалить всё" и оба варианта работают корректно (проверяется тестом: после "удалить всё" в БД нет записей за эту сессию).
- Wizard доступен повторно из Настроек в любой момент и не изменяет/не дублирует ранее созданные записи.
- Расчёт накопленного дохода по вкладу на Шаге 3 (предпросмотр) совпадает с методом `get_accrued_income()` из основной модели Deposit.
